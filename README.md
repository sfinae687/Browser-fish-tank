# 计算水族箱

一个运行在 Chromium 里的生态鱼缸。

**鱼缸不是被画出来的，是被算出来的。** 每一块几何景观、每一束光、每一度水温，
都是某个种子经过一串算法得到的结果。整缸状态是 `(种子, 时间)` 的纯函数 ——
所以它不看的时候不必运行、一串种子就能分享、多个表面各自计算也不会打架。

美术方向是**几何光影 · 梦幻**：干净的几何体、柔和的面光、体积光与失焦光斑。
不追求写实 —— 层次靠光拉开，靠的是算法本身好看，而不是把噪声堆得像照片。

设计定案见 [DESIGN.md](DESIGN.md)。

```bash
pnpm install
```

### 玩家操作为什么要走「日志」

每个表面各持一份世界。如果点击直接改本地世界，那么在新标签页里投的食，
覆盖层那份世界完全不知道 —— 覆盖层稍后写回快照就把这次投食抹掉了。

所以操作会变成**带时间戳的记录**：各表面在下一次推进时，把它应用到
**它发生的那个 tick 上**。于是两个表面各自重放同一份日志、世界保持逐位一致，
而且关掉标签页三天再回来，这三天里的投食会在快进时被正确补上。

### 生态是什么样的

变温动物：水温每升高 6°C 代谢翻一倍 —— 水温不只是画面上的数字，
它直接决定鱼吃多少、饿多快。

**这套生态会收敛到一个稳定的共存平衡点，不会自发振荡** ——
这是 Holling II 型功能反应 + 猎物避难所的必然结果，真实鱼缸也是这样。
真正的藻华需要**外部扰动**（过量投食、改变光照），那是 P5 里玩家扮演的角色。

### 鱼是怎么来的

每条鱼由一段**基因组**决定：脊柱段数、体长、体型曲线、各鳍的位置与大小、
花纹、配色、巡游速度、胆量、合群程度、偏好水深、食性。全部是定点整数，
全部由种子派生 —— 同一个种子长出同一群鱼。

```bash
node tools/test.mjs --trace    # 打印基因组表与鱼群状态
```

鱼群**不做速度积分**，位置是 `(种子, 世界时间)` 的纯函数。
所以跳到任意时刻都只是重新求值一次，没有快进问题，两个表面各算各的也必然一致。

### 植物是怎么长出来的

珊瑚不是画出来的，是**算出来的**：给一团吸引点，枝条朝最近的吸引点生长，
长到哪就把周围的吸引点吃掉，直到吃光。同一个种子长出的珊瑚完全一样。

```bash
node tools/flora-debug.mjs          # 骨架拓扑统计 + 可视化导出到 .preview/
node tools/flora-debug.mjs --seed=xxx --stats
```

这个工具是这一轮最有用的东西 —— 当渲染出来的形态不对时，
「骨架长错了」和「光栅化画错了」是完全不同的两个 bug，
而它们隔着烘焙和着色器两层。能直接把中间层画出来，定位就变成了一次对比。

## 几个值得知道的实现约束

写在这个项目里容易踩的坑，都在源码注释里展开了，这里只列结论：

- **命名随机子流**（`core/rng.ts`）：子流身份由 `(根种子, 路径)` 决定，与取数顺序无关。
  往 `flora.coral` 里加代码不会移动 `fauna.genome` 的任何一个比特。
  这条纪律必须从第一天立起来，事后补救不可能。
- **离屏纹理的坐标约定**（`render/shaders/post.ts`）：场景 pass 用 y 向下的 uv 写入 FBO，
  合成 pass 采样时必须把 y 转回去。少这一步整个场景会上下颠倒。
- **不要用 `smoothstep(e0, e1, x)` 且 `e0 >= e1`**：GLSL 规范说结果未定义。
  用 `sstepDown()`，理由见 `shaders/common.ts`。
- **别在极坐标里对角度做噪声当光柱**：会得到一圈硬边扇形。
  真实水下光柱是近乎平行的一组光轴，见 `lightShafts()`。
- **别用「角度的函数」去扰动形状半径**：所有细节会变成放射状，形状变成扇贝。
  用二维噪声场，见 `hardscapeSDF()`。
- **别在着色器模板字符串的注释里写反引号**：会直接终结模板字面量。
  `build.mjs` 里有一道检查专门挡这个。
- **content script 必须是 IIFE**：MV3 不支持 ESM 格式的 content script。
  这是四种产物里唯一不能统一格式的地方。
- **无头截图不能用固定延时**：`--virtual-time-budget` 不等 GPU 出图。
  页面通过 `window.__aqua.ready` 报告就绪，脚本用 CDP 轮询它。
- **模拟里不能用 `Math.sin/cos/exp/pow/log`**：规范说它们是 implementation-approximated，
  不同 V8 版本最后一位可能不同。只用 `+ − × ÷` 和 `Math.floor/round/min/max`。
- **散射介质用 `mix` 不用 `+`**：光柱和 bokeh 既是发光体也是遮挡物，
  用加法会把背后的砂面无限叠加到纯白。
- **落在表面的光用乘不用加**：焦散要乘在反照率上，再强的光晒在白砂上也只接近白。
- **几何体的边界不能有噪声**：噪声会让所有细节变成放射状、形状变成星形。
  不规则要靠尺寸与位置的分布去要。
- **发光感来自光效，不来自基色**：基色压暗、让光做功。两边同时提亮会立刻过曝。
- **离屏纹理的坐标约定**（重复一次，因为它最坑）：场景 pass 用 y 向下的 uv 写入 FBO，
  合成 pass 采样时必须把 y 转回去。
- **JS 的位运算是 32 位的**：`isqrt` 里的 `>>` 在参数超过 2^31 时静默截断，
  症状是「有的珊瑚长得好、有的一根都不长」。数值函数要单独写单元测试。
- **不要按数组下标连线**：空间殖民每轮批量追加节点，`i` 的父节点不是 `i-1`。
- **形态生成留在 CPU**：它决定了「同种子是否同缸」，必须逐位可复现，
  而 GPU 浮点跨显卡不保证一致。WebGPU compute 用在逐帧的连续场上。
- **会变形的东西不能用烘焙**：植物烘焙成纹理，因为它们生成一次就不变；
  鱼每帧都在变形，必须走真实顶点管线。
- **定点归一化的放大倍数要按量的量级选**：位移量级 1e-3 时放大 2^20 会让
  「单位向量」长度变成 1.27。用 2^40。
- **斥力写成「单位方向 × 有上界的步长」**：`(S−d)/d·d` 这种自然写法在 d→0 时爆炸。
